# gocode-ops 使用手册（helper.md）

本手册由 `gocode-ops init` 释放（随二进制内置，版本随程序更新）。
阅读本文件即可完整使用 gocode-ops：程序架构、命令行用法、配置文件、
模板改写、交互界面与安全模型。

---

## 1. 程序架构

gocode-ops 是面向 Linux 运维/实施/部署场景的 AI 助手，人在环；
`auto` 子命令提供同生态的全自动运维引擎（无人值守，比赛/评审
用途），两者共用同一套公共底座与安全守卫（internal/common）：

```text
gocode-ops      交互式运维助手：TUI 对话下达任务，高危命令确认，
                L0 快检按需触发（l0_snapshot 工具）；非终端退化一次性执行
      auto 子命令 全自动运维引擎：协议驱动巡检排障，退出码 +
                result.json 可机器评分；核心是 autopilot 库，可被直接
                import 嵌入托管
init            初始化工作目录：生成 .gocode/ 配置目录与模板
```

关键设计：

- **一套内核，两种形态**：交互式运维助手与全自动运维引擎 共用 common 公用内核——L0 确定性
  快检、findings 三态、基线、报告与信息注入（AGENTS.md + 模板变量）
  单一来源；提示词两种形态独立成文、独立覆盖（prompt.assistant.md / prompt.engine.md）；
  差异只在驱动方式与报告策略：交互是操作员在环（模型按需调用
  l0_snapshot；报告按需生成——操作员明确要求时经 generate_report 工具，
  不主动生成），全自动运维引擎是 PolicyAuto + 收敛循环（报告由引擎每轮
  自动渲染，无人值守需要结果给人看）；
- **命令优先**：巡检、诊断、日志分析直接执行 Linux 命令，不提供薄封装
  工具（无 sys_health/log_tail 之类），模型对命令的掌握远好于任何封装；
- **远程能力工具族**：`remote_terminal` / `remote_batch` / `remote_upload`
  / `remote_download` / `remote_copy` / `remote_file` / `remote_list`，远程与本地同一套
  逻辑、不同的呈现；
- **凭证零泄露**：密码/私钥只存本机清单文件，模型永远看不到凭证，
  也无法自建 ssh/scp 连接（守卫硬性拦截）；
- **安全守卫**：高危命令按策略确认/放行/拒绝，硬性破坏性命令永远禁止；
- **审计**：所有工具调用与守卫决策写入 `ops-audit.log`，全程可回溯；
- **模型**：当前版本仅支持 DeepSeek（模型固定 `deepseek-v4-flash`，
  API Key 从环境变量 `DEEPSEEK_API_KEY` 读取）。

## 2. 快速开始

```bash
# 1. 初始化工作目录：生成 .gocode/ 配置目录（hosts.yaml/AGENTS.md/
#    prompt.assistant.md/prompt.engine.md/helper.md）
gocode-ops init

# 2. （可选）编辑 .gocode/hosts.yaml 填入远程主机
#    （未配置清单时 gocode-ops 只操作本机）

# 3. 交互 TUI（可带初始任务）
DEEPSEEK_API_KEY=... gocode-ops "巡检系统健康"

# 4. 或全自动运维引擎（auto 子命令，报告实时生成在工作目录 report.md）
DEEPSEEK_API_KEY=... gocode-ops auto --timeout 2h
```

> 未 init 的工作目录也能运行（本机巡检），但启动时会提示执行
> `gocode-ops init`——远程主机清单、环境信息约定与提示词覆盖都依赖
> `.gocode/` 目录。

## 3. 命令行使用说明

### 3.1 gocode-ops 全局参数

三个参数对交互式运维助手/init 子命令生效，统一定义在根命令上：

| 参数 | 简写 | 默认 | 说明 |
|------|------|------|------|
| `--dir` | `-d` | `.` | 工作目录（报告/脚本/审计日志与 `.gocode/` 配置的落盘处） |
| `--provider` | `-p` | `deepseek` | 模型提供商（当前仅支持 `deepseek`；多供应商支持后续经配置文件提供） |
| `--risky` | — | `ask` | 高危命令策略：`ask` 逐条确认 / `allow` 自动放行 / `deny` 一律拒绝 |

用法示例：

```bash
gocode-ops -d ./work --risky deny "只读诊断磁盘问题"
```

### 3.2 auto 子命令（全自动运维引擎）

| 参数 | 简写 | 默认 | 说明 |
|------|------|------|------|
| `--timeout` | — | 0（不限） | 全局时限（如 `30m`/`2h`）；到点未收敛如实非零退出 |
| `--json` | — | `<工作目录>/result.json` | 机器评分结果输出路径 |

（`-d`/`-p` 继承根命令全局参数；`--risky` 不生效，引擎使用独立的
PolicyAuto 策略。）

退出码约定：

- `0`：收敛——连续 2 轮无新线索且全部确认故障已处置；
- `1`：未收敛/失败/全局时限已到（证据不足的线索进报告"待查"区，
  处置达限未修由停滞检测强制非零退出）；
- 运行中 Ctrl+C 提前结束。

`result.json` 结构：`converged`（布尔）、`error`（未收敛原因）、
`elapsed`（耗时）、`report`（报告路径）、`findings`
（total/confirmed/remediated/pending/dismissed 计数）。

### 3.3 交互式运维助手（gocode-ops 默认）

```text
gocode-ops [任务...]
```

- 终端环境进入 TUI；`任务...` 为初始任务（多个参数用空格连接成一句）；
- 非终端（管道/脚本）退化为非交互模式：执行一次任务后退出，回答走
  stdout、过程走 stderr；高危命令一律拒绝（无操作员确认通道）；
- 能力介绍/帮助/闲聊类问题直接用知识回答（不调工具、不触发巡检）；
  指向目标系统的任务才会执行命令，需要全局状态时模型按需调用
  `l0_snapshot` 确定性快检工具。

### 3.4 init 子命令

```text
gocode-ops init              # 当前目录
# 指定工作目录（目录不存在会自动创建；auto/交互式助手同样用 -d 指定）
gocode-ops init -d /work/ops
```

在工作目录下创建 `.gocode/` 配置目录并释放模板：

| 文件 | 权限 | 覆盖策略 | 作用 |
|------|------|---------|------|
| `hosts.yaml` | 0600 | 已存在不覆盖 | 远程主机清单（凭证所在） |
| `AGENTS.md` | 0644 | 已存在不覆盖 | 环境信息约定（创建空文件，填写后注入） |
| `prompt.assistant.md` | 0644 | 已存在不覆盖 | 交互式运维助手系统提示词（init 释放内置正文，可直接改写） |
| `prompt.engine.md` | 0644 | 已存在不覆盖 | 全自动运维引擎系统提示词（init 释放内置正文，可直接改写） |
| `helper.md` | 0644 | 总是刷新为内置版本 | 本使用手册 |

`.gocode/` 目录是完整的可复用配置集：随工作目录打包、拷贝即可迁移。

## 4. 配置文件（.gocode/）

### 4.1 hosts.yaml —— 远程主机清单

```yaml
# 字段说明:
#   name            主机别名（模型只能看到这个名字）
#   address         地址，可带端口（默认 22）
#   user            登录用户
#   key_file        私钥路径（推荐）；与 password 二选一
#   password        明文密码（不推荐，建议用 key_file）
#   host_key_check  是否校验 known_hosts（默认 true；首次连接失败时
#                   可设 false，需自评 MITM 风险）
hosts:
  - name: web-01
    address: 10.0.0.11
    user: root
    key_file: ~/.ssh/id_ed25519
  - name: db-01
    address: 10.0.0.12:22
    user: ops
    key_file: ~/.ssh/id_rsa
```

- 凭证仅存本机，模型永远不可见（只能看到别名）；请勿把本文件提交 git；
- 存在且含主机时：交互式运维助手启用远程工具族，全自动运维引擎巡检
  远程主机（清单全部）；否则只操作本机。

### 4.2 AGENTS.md —— 环境信息约定

交互式运维助手与全自动运维引擎 都会自动把本文件合入模型上下文（存在且含正文即注入；
空文件/全注释视为未配置，不注入）。只写**信息**，不写**故障规则**：

- 环境预期：操作系统/容器化/部署形态/组件清单；
- 业务方提示：重点怀疑方向、已知变更窗口；
- 合规要求：本系统为无人值守，所有决策自动进行并留痕。

```markdown
# 环境信息约定
- 环境为 3 节点 web 服务：web-01/02 运行 nginx，db-01 运行 MySQL 8
- 部署方式为 Docker Compose，日志在 /var/log/app/ 下
```

> init 只创建空文件（空文件/全注释视为未配置，不注入）；文件内容
> 原样注入模型上下文，不做任何剥离——请直接写要生效的信息。
> 支持 `{{workdir}}`/`{{hosts}}`/`{{host}}` 模板变量（加载时渲染）。

### 4.3 prompt.assistant.md / prompt.engine.md —— 系统提示词

两种形态的系统提示词独立成文，文件也分为两个（互不影响）。**文件就是
系统提示词**：init 把内置正文释放进文件，程序加载时读取文件、渲染模板
变量、追加共享构建块，直接作为系统提示词使用。

- `prompt.assistant.md`：交互式运维助手（TUI）的系统提示词。init 释放的
  内置正文覆盖产品专属面（身份/环境事实/边界/命令清单/任务处置 SOP/
  部署优化）；共享安全规则、追查方法论与交互规则（高危策略说明/
  ask_operator/摘要输出）由程序在加载时强制追加，无需在文件中重复。
- `prompt.engine.md`：全自动运维引擎的系统提示词。init 释放的内置正文
  覆盖引擎专属面（身份/系统协作 SOP）；共享安全规则与追查方法论由程序
  强制追加。注意：引擎的阶段任务提示与 JSON 输出契约由引擎另行附加，
  无需在此重复。

**生效规则（简单一条）**：文件内容 = 生效的系统提示词正文——init 释放
的内置版本直接生效，改写后立即生效；删除文件/空文件/全注释时回退内置
提示词。程序升级不会自动改写已释放的文件（init 不覆盖已存在文件），
想跟随新版本内置提示词时，删除对应文件后重跑 `gocode-ops init`。

**内容原样使用**：文件内容就是注入的系统提示词正文，程序不做任何剥离
——说明都在本手册，不要在文件里写程序说明，直接写要生效的提示词。
文件内容支持以下模板变量（加载时渲染）：

| 变量 | 渲染为 |
|------|--------|
| `{{workdir}}` | 工作目录绝对路径 |
| `{{hosts}}` | 巡检目标清单（逗号连接；无清单时为本机显示名） |
| `{{host}}` | 本机显示名（hostname） |

未知变量原样保留（拼写错误自查可见）。两个文件互相独立：改写
`prompt.assistant.md` 不影响 全自动运维引擎，反之亦然。

## 5. 交互 TUI

界面自上而下：**顶部信息条**（状态/主机/高危策略/远程主机数/token
用量）、**标签页主区**（对话/工具调用/远程主机）、**两行输入框**、
**快捷键提示行**。

| 键位 | 作用 |
|------|------|
| `Enter` | 发送任务（Shift+Enter 亦可，兼容部分终端） |
| `Ctrl+↑` / `Ctrl+↓` | 切换历史任务 |
| `Ctrl+C` | 中断当前任务；空闲时退出（输入框聚焦同样生效） |
| `Ctrl+P` | 命令面板（新会话/主机/用量/帮助/退出） |
| `tab` / `shift+tab` | 切换焦点（输入框 ↔ 标签页） |
| `←` / `→` | 切换标签页 |
| `r` / `p` | （远程主机页）刷新清单 / 探测连通性 |
| `?` | 帮助面板 |

输入框内可直接键入内置命令（与命令面板等价）：

| 命令 | 作用 |
|------|------|
| `/help`（`/?`） | 显示帮助与任务示例 |
| `/new` | 清空对话上下文与用量，开始新一轮 |
| `/hosts` | 切换到远程主机页 |
| `/tokens` | 显示累计 token 用量 |
| `/exit`（`/quit`） | 退出 |

L0 确定性快检由模型**按需调用** `l0_snapshot` 工具触发（线索写入
findings 待查区、基线落盘、摘要进上下文）；**报告按需生成**——操作员
明确要求时（"出个报告"/"生成巡检报告"）模型调用 `generate_report`
工具渲染 `report.md` 并返回路径，日常问答与处置任务不主动生成。
交互式运维助手与全自动运维引擎 共用同一份工作区状态（findings.json / baseline.json /
report.md），状态跨产品延续；`report.md` 在全自动运维引擎中由引擎每轮
自动渲染（无人值守的产物），交互形态只在显式要求时渲染。能力介绍/
闲聊类问题不触发任何工具。

高危命令执行前弹出确认框（界面中央，焦点锁定）：缺省 y/n 选项可
直接按键回答；守卫确认新增第三个选项 **a = 本会话全部放行**（后续
常规高危变更命令不再逐条打断，硬性禁止与风险审查照旧拦截）；带选项
的 `ask_operator` 提问用 ↑/↓ 选择后 Enter 确认，Esc 取消；选项不
满足时可选择「其他」输入自定义回答。

## 6. auto 子命令（全自动运维引擎）说明

- **协议骨架**：survey（巡检三合一：环境认知 → 全域基线 → 安全隐患
  专项，一次模型会话完成）执行一次；此后主循环：L0 确定性快检 →
  DeepDive（线索深挖）→ Respond（处置 + 验证 + 回滚 + 引擎确定性
  复检）→ Report（实时渲染）；收敛前对剩余待查线索终裁一次；
- **L0 确定性层**：纯代码零延迟快检（CPU/内存/磁盘/inode/僵尸进程/
  失败服务/错误日志/SUID/能力位/配置漂移等），只产线索不产结论；
- **验证回路**：发现三态（待查/确认/排除），处置只对已确认故障，
  处置方案满足三件套契约（理由+验证+回滚）；
- **安全**：只读自动放行、处置命令经契约校验后登记执行、未登记高危
  拒绝、硬性禁止永远拒绝。

工作目录产物（交互式运维助手与全自动运维引擎 共用）：`report.md`（巡检报告：全自动引擎每轮实时
渲染、终态闭合；交互助手按操作员要求经 `generate_report` 按需生成）、
`env.json`（环境画像）、`findings.json`（发现三态）、
`baseline.json`（多轮基线）、`phases.json`（阶段记录）、
`ops-audit.log`（守卫审计，任何形态恒写）、`result.json`（全自动运维引擎机器评分结果）、
`desired.json`（期望状态：角色/期望/策略/同构组，可选）、
`memory/`（经验库与主机档案，越用越懂）、`workbench.json`（认知工作台）。

### 6.1 并行子代理（默认开启，`--parallel` 可调）

DeepDive/Respond/终裁批次并行执行（子代理池，默认 6 个独立 agent 会话；
DeepDive **每条线索一个独立会话**并行追查，Respond 每批 2 个故障）：
多问题同时追查与处置，吞吐线性提升；单批失败只影响该批（下轮重试）。
模型 API 限流环境可 `--parallel 1-4` 调低。

### 6.2 watch 模式（常驻守护，`--watch`）

先收敛当前问题，再按周期（如 `--watch 5m`）持续感知：新问题自动进入
追查/处置；**已处置的问题复发（被 L0 重检出）自动重新处置**。Ctrl+C
退出。

### 6.3 期望状态（`--init-desired`，可选）

```bash
gocode-ops auto --init-desired -d ./work   # 生成模板后编辑 .gocode/desired.json
```

声明"这台主机应该是什么样"（角色模板/必须监听端口/必须运行服务/禁止
SUID 路径/安全策略/同构组）——引擎按 **期望-观测偏差** 检出问题（超出
探针规则面）；未声明的主机行为与旧版一致。交互式运维助手可用
`update_desired` 工具由操作员声明（"这个端口是正常的"→ 不再误报）。

### 6.4 记忆（自动，无需配置）

处置成功/排除的发现自动沉淀经验库与主机档案（误报率统计、恢复模式、
历史操作）；大脑经 `recall` 复用经验——同一环境越跑越快。交互式运维
助手把**操作员批准过的高危命令**沉淀进档案（人在环背书）。

## 7. 示例

```bash
# 交互：本机巡检
gocode-ops "巡检系统健康"

# 交互：远程批量
gocode-ops "对 all 主机批量执行磁盘巡检"

# 交互：部署实施
gocode-ops "把本地 dist 目录部署到 web-01 的 /srv/www，先备份旧版本，部署后验证服务"

# 交互：能力咨询（不触发巡检）
gocode-ops "你能帮我做什么？"

# 非终端（脚本/管道）：一次性执行
echo "巡检磁盘" | gocode-ops > answer.txt

# 全自动运维引擎：比赛/评审用途（退出码 + result.json）
gocode-ops auto --timeout 2h
gocode-ops auto -d ./work --timeout 30m --json ./result.json

# 全自动运维引擎：并行子代理（默认 6）与常驻守护
gocode-ops auto -d ./work --parallel 6 --timeout 2h
gocode-ops auto -d ./work --watch 5m
```

## 8. 安全模型

- 凭证只在本地 `.gocode/hosts.yaml`（0600），模型永远看不到也不需要；
- 守卫硬性禁止读取任何凭证材料（`~/.ssh`、`/etc/shadow`、`.pem/.key`、
  `.my.cnf`、`~/.aws`、`~/.kube`、`.gocode/` 等）与自建连接
  （ssh/scp/sftp/sshpass）；
- 硬性破坏性命令（`rm -rf /`、`mkfs`、`dd of=/dev/sd*`、fork 炸弹等）
  永远不允许执行，即使操作员同意；
- 高危命令以运行 agent 的用户身份执行；需要 root 时使用 `sudo`，
  守卫同样拦截并要求确认；
- 交互策略 `--risky`：`ask` 逐条确认（默认，确认时可选 a 一次性
  放行本会话全部常规变更）/ `allow` 自动放行 / `deny` 一律拒绝。

## 9. 工具与超时

| 工具 | 超时 | 说明 |
|------|------|------|
| `terminal` | 默认 60s；`timeout` 参数可声明（上限 10m） | 本机 shell 主力工具；预计超过 30s 的命令（安装/编译/迁移）请声明 timeout；输出超长保留头尾 |
| `task_run` / `task_status` / `task_stop` | 无硬上限（后台） | 小时级长任务（大编译/数据迁移/压测）：后台启动立即返回，日志落工作目录 `tasks/`，轮询或停止 |
| `remote_terminal` / `remote_batch` | `timeout_s` 参数（默认 30s，上限 10m） | 长命令请声明 timeout_s；更长的任务远端 nohup 后台执行后轮询 |
| `remote_copy` | — | 远端↔远端复制文件/目录（本机 SFTP 双程中转，凭证不出本机；scp 被守卫禁止的通道） |
| `remote_upload` / `remote_download` / `remote_copy` | 断点续传 + 完成后字节数校验 | 大文件中断后重传不从头再来；传坏立即发现；上传 mode 缺省继承本地权限 |
| `l0_snapshot` | 快检轮 30s | 确定性快检（线索/基线/事实），交互式运维助手按需调用；全自动运维引擎由引擎主循环自动跑 |

## 10. 常见问题

- **忘了 init？** 交互式运维助手与全自动运维引擎 都能运行本机巡检，但远程能力与配置
  注入需要 `.gocode/`；运行 `gocode-ops init` 即可补上。
- **改了 prompt.assistant.md / prompt.engine.md 不生效？** 文件就是系统
  提示词，加载即生效；全注释/空文件视为未配置（回退内置）——确认正文
  含非注释行。
- **远程连接失败？** 「远程主机」页按 `p` 探测连通性。host key 校验
  失败会区分两种情况提示：known_hosts **无该主机条目**（key is unknown）
  或**指纹不匹配**（key mismatch）——都需在 gocode-ops 同一运行环境、
  以与清单 `address` 完全一致的名字（hostname/IP/端口形式）录入指纹；
  主机重装/重建、IP 复用导致指纹变化时先 `ssh-keygen -R` 清除旧条目
  再重录；或对单台主机设 `host_key_check: false`（需自评 MITM 风险）。
- **目标系统要求**：Linux（巡检命令依赖 procps/systemd/GNU coreutils）；
  上传/下载走 SFTP，依赖远端 `sftp-server`（OpenSSH 默认启用）。
- **问"你能做什么"触发了巡检？** 交互提示已内置能力边界规则（知识类
  问题不调工具）；若仍触发，请检查 prompt.assistant.md 是否移除了
  该规则（交互规则由程序追加，正常不会丢）。
